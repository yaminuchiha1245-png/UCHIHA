# Client Services Store

هذه النسخة مخصّصة لعميل مستقل ومبنية فوق UCHIHA Store بدون تعديل فرع `main`.
مصدر العمل الحالي هو الفرع:

```text
client/ios-android-services-store-v1
```

## واجهة العميل

القائمة الرئيسية:

- 📱 منتجات iOS
- 🤖 منتجات Android
- 💎 Diamond FF
- 💳 شحن رصيد
- 👤 حسابي

منتجات iOS:

- 📜 الشهادات
- 📂 الملفات
- 🌐 البروكسي
- 🖥️ البنلات

منتجات Android:

- 🖥️ البنلات
- 📂 الملفات
- 🌐 البروكسي

الحساب يدعم رتبتين:

- ⭐ عميل
- 👑 موزع

يمكن للموزع الحصول على نسبة خصم عامة أو سعر موزع ثابت لمنتج محدد.

## إعداد أول تشغيل

بعد تثبيت الاعتمادات:

```bash
pip install -r requirements.txt
python client_setup.py
```

صاحب البوت هو من يدخل:

- Telegram BOT_TOKEN
- Telegram ADMIN_ID
- مسار قاعدة البيانات إن أراد تغييره

لا يتم إدخال توكنات مزودي المنتجات في هذا الإعداد. تُضاف من داخل لوحة إدارة البوت بعد تشغيله.

لتشغيل نسخة العميل:

```bash
python client_store_launcher.py
```

## إدارة مزودي API

من لوحة الإدارة:

`🧰 إدارة متجر العميل → 🔌 مزودو API`

يمكن لصاحب البوت:

- إضافة مزوّد جديد.
- إدخال Base URL ومسار الكتالوج.
- إدخال أو تبديل API Token.
- اختيار طريقة المصادقة: Bearer أو X-API-Key أو Query Parameter أو تلقائي أو بدون مصادقة.
- تفعيل/إيقاف المزوّد.
- تشغيل مزامنة الكتالوج يدويًا.

توكن المزوّد يُشفّر باستخدام Fernet ولا يُعرض كاملًا بعد حفظه. رسالة تبديل التوكن تحذف من المحادثة قدر الإمكان بعد قراءتها.

المزامنة العامة للكتالوج قراءة فقط. لا تنفذ عمليات شراء على API المزوّد.

## ترتيب المنتجات

منتجات API الجديدة تدخل إلى:

`📥 غير مرتبة`

صاحب البوت يحدد مكان المنتج ثم يعتمده. بعد الاعتماد ينتقل إلى:

`✅ تم ترتيبها`

يمكن تحديد:

- iOS / Android / Diamond FF.
- القسم الفرعي عند الحاجة.
- سعر البيع.
- سعر الموزع الاختياري.
- رقم الترتيب.
- تفعيل أو تعطيل المنتج.

المزامنة اللاحقة تحدث تكلفة المزوّد والبيانات الخام، لكنها تحافظ على سعر البيع ومكان المنتج الذي رتبه صاحب البوت.

## المنتجات اليدوية

يمكن إنشاء منتج يدوي بدون أي API من:

`🧰 إدارة متجر العميل → ➕ منتج يدوي`

بعد إدخال الاسم والسعر وتعليمات التسليم، يدخل المنتج إلى `📥 غير مرتبة` ليتم وضعه في القسم الصحيح.

الشراء اليدوي يعمل فعليًا من رصيد العميل داخل معاملة قاعدة بيانات، ينشئ طلبًا ويضيف سجل خصم ويرسل إشعارًا لصاحب البوت.

## شراء منتجات API

زر شراء المنتج القادم من API لا ينفذ طلبًا خارجيًا حتى يتم تركيب Adapter موثوق لذلك المزوّد. السبب أن مسارات الشراء والحقول المطلوبة تختلف من مزوّد لآخر، ولا يجوز إرسال عملية شراء أو خصم رصيد اعتمادًا على تخمين.

## الأمان والعزل

- متجر UCHIHA الأصلي على `main` لا يتم تعديله.
- نسخة العميل تعمل من Launcher مستقل.
- مزامنة JS4Card القديمة معطلة افتراضيًا في نسخة العميل.
- Storefront Web/API القديمة معطلة افتراضيًا في نسخة العميل.
- Binance auto payment معطل افتراضيًا ويمكن لصاحب البيئة تفعيله صراحة إن احتاجه.
- روابط مزودي API يجب أن تكون HTTPS افتراضيًا.
- ملفات `.env` والمفاتيح الحقيقية لا يجب رفعها إلى GitHub.
- مفتاح تشفير المزودين يجب أن يبقى مع قاعدة بيانات العميل/النسخ الاحتياطية الآمنة.

## الفحص

GitHub Actions يشغّل:

- Python 3.12.
- تثبيت `requirements.txt`.
- `py_compile` لملفات نسخة العميل.
- استيراد الوحدات.
- اختبارات تشفير التوكنات، قراءة الكتالوج، طرق مصادقة المزود، وتسعير الموزعين.

نجاح CI يعني أن الكود اجتاز هذه الفحوص، لكنه لا يثبت أن API خارجيًا بعينه يعمل قبل إضافة بيانات ذلك المزوّد وإجراء اختبار اتصال حقيقي آمن.
