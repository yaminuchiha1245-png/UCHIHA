# UCHIHA — خارطة الطريق الموحدة

ترتيب الأولويات مبني على حالة المشاريع الحالية، مع الحفاظ على أي خدمة شغالة وعدم إجراء نقل خطير للملفات.

## الأولوية 1 — تثبيت UCHIHA Builder للإنتاج

الهدف: جعل `builder/v1-platform` يمر ببوابات الإنتاج بدل اعتباره جاهزًا لمجرد وجود الكود.

المهام:

- إصلاح آخر فشل في CI على فرع Builder.
- تشغيل الاختبارات الكاملة مع PostgreSQL حقيقية.
- تشغيل `smoke-vps.sh` و`launch-audit.sh` على بيئة الهدف.
- التحقق من آخر Schema ومهاجرات قاعدة البيانات.
- التحقق من Worker وQueue وProvisioning.
- اختبار تسجيل الحساب والاشتراك وإنشاء متجر واحد فقط لكل اشتراك.
- اختبار المحفظة، الطلبات، الدفعات، الدعم، KYC و2FA.
- اختبار Telegram الحقيقي في بيئة Staging قبل Production.
- اختبار Provider الحقيقي في بيئة آمنة قبل تفعيله للعملاء.
- تجهيز Object Storage وSigned URLs إذا كان الاستخدام الإنتاجي يحتاج ملفات كثيرة.
- بناء واختبار تطبيق Android، ثم تحديد مسار iOS.

شرط الإغلاق: نجاح اختبارات الإنتاج والـCI وعدم وجود مسار Demo يستطيع أن يصبح مصدر بيانات حقيقي.

## الأولوية 2 — UCHIHA Debt Store Release

الهدف: تحويل APK Debug العامل إلى إصدار نهائي قابل للتوزيع بثقة.

المهام:

- اختبارات منطق الديون: شراء، دفعة، FIFO، العملات، سعر الصرف.
- اختبار النسخ الاحتياطي والاستعادة على بيانات كبيرة.
- اختبار PDF وCSV.
- اختبار PIN والبصمة على أجهزة Android مختلفة.
- اختبار الواجهة على أحجام شاشات مختلفة.
- معالجة أي Crash أو ANR يظهر على الأجهزة.
- إعداد Keystore آمن خارج GitHub.
- بناء Signed Release APK/AAB.
- إضافة Workflow Release منفصل عن Debug.

شرط الإغلاق: إصدار موقّع يثبت ويعمل على الأجهزة المستهدفة مع اختبارات أساسية ناجحة.

## الأولوية 3 — التحقق الحي لـ UCHIHA Store

الهدف: إنهاء الفرق بين الاختبارات المحلية والبيئة المالية الحقيقية.

المهام:

- اختبار Binance Pay ID بمبلغ صغير في البيئة الحقيقية.
- اختبار USDT TRC20 بمبلغ صغير والتحقق من TXID.
- التحقق من منع تكرار نفس المعاملة.
- اختبار JS4Card بطلب منخفض المخاطر والتأكد من Idempotency.
- مراجعة Logs وRate Limits بعد الاختبارات.
- التأكد من أن الأسرار موجودة في Railway فقط.

شرط الإغلاق: نجاح اختبار حي لكل تكامل مالي أساسي دون تكرار خصم أو رصيد.

## الأولوية 4 — Sham Cash Automation

الهدف: الانتقال من مركز إداري آمن إلى اعتماد تلقائي موثوق.

المهام:

- الحصول على توثيق API الرسمي للحركات.
- تحديد معرف الحركة والحساب والعملة والمبلغ والوقت والحالة.
- بناء Verifier مستقل.
- إضافة Idempotency ومنع إعادة استخدام الحركة.
- إضافة فترة صلاحية للطلب ومراجعة يدوية للحالات الملتبسة.
- اختبارات وهمية ثم اختبار حي صغير.

شرط الإغلاق: لا يتم شحن أي رصيد تلقائيًا إلا بعد تطابق حركة رسمية مؤكدة.

## الأولوية 5 — تنظيف الفروع

بعد تثبيت المشاريع الثلاثة:

- مقارنة `agent/*` و`codex/*` و`copilot/*` مع فرع المشروع المقابل.
- إبقاء أي فرع يحتوي تغييرات غير مدمجة فقط.
- أرشفة أو حذف الفروع المنتهية.
- الاحتفاظ بنقاط Backup قليلة وواضحة بدل عشرات الفروع المتشابهة.
