# خريطة مستودع UCHIHA

هذه الوثيقة هي المرجع المختصر لمعرفة ما هو مشروع فعلي وما هو فرع تطوير أو أرشيف.

## المشاريع الرئيسية

### 1) UCHIHA Store

- الفرع: `main`
- الحالة: نشط ومتقدم وقريب من الإنتاج.
- التقنية: Python / aiogram / FastAPI / SQLAlchemy / SQLite / aiohttp.
- الوظيفة: متجر رقمي + بوت Telegram + لوحة إدارة + موقع عميل + رصيد وطلبات ودفع.
- التكاملات: JS4Card، Binance Pay ID، USDT TRC20، Sham Cash.
- التوثيق: `docs/UCHIHA_STORE.md`.

### 2) UCHIHA Builder / Platform

- الفرع: `builder/v1-platform`
- الحالة: نشط، Release Candidate، لكن لا يعتبر إنتاجيًا نهائيًا قبل اجتياز بوابات التحقق.
- التقنية: Node.js 22 / Fastify / PostgreSQL / Workers / PWA / Mobile.
- الوظيفة: منصة SaaS متعددة المستأجرين لإنشاء وإدارة المتاجر والخدمات والحسابات والمحافظ والطلبات.
- المصدر التشغيلي لهذا المشروع هو مجلد `builder/` داخل فرعه.
- لا يجب دمج ملفاته يدويًا في `main` دون خطة ترحيل واضحة.

### 3) UCHIHA Debt Store

- الفرع: `debt-store-build`
- الحالة: نشط، APK Debug يُبنى بنجاح عبر GitHub Actions.
- التقنية: Android + WebView/JavaScript محلي داخل التطبيق.
- الوظيفة: دفتر ديون للمحل، عملاء، شراء، دفعات، عملات، حاسبة، سجل، نسخ احتياطي وتصدير.
- المطلوب لاحقًا: اختبارات أجهزة + Release موقّع APK/AAB.

## الأنظمة الفرعية داخل UCHIHA Store

هذه ليست مشاريع مستقلة:

- `api_js4card.py`: عميل JS4Card.
- `binance_admin.py`: إدارة Binance.
- `binance_compat.py`: توافق وإعدادات Binance.
- `tron_verifier.py`: التحقق من TRON/USDT.
- `shamcash_admin.py`: مركز Sham Cash.
- `shamcash_payment_ui.py`: واجهة Sham Cash.
- `storefront_*`: وحدات واجهة/API/إدارة/حماية المتجر.
- `js4card_price_precision.py`: معالجة دقة الأسعار.
- `js4card_purchase_options.py`: خيارات وحقول الشراء.

## تصنيف الفروع

### فروع إنتاج/مشاريع يجب الحفاظ عليها

- `main`
- `builder/v1-platform`
- `debt-store-build`

### فروع أرشيف/نسخ احتياطية

أي فرع يبدأ بـ:

- `archive/`
- `backup/`

يعتبر مرجعًا تاريخيًا ولا يجب تطوير ميزات جديدة عليه.

### فروع تطوير مؤقتة

أي فرع يبدأ بـ:

- `agent/`
- `codex/`
- `copilot/`
- `fix/`
- `deploy/`

لا يعتبر مشروعًا مستقلًا. يجب الاحتفاظ به فقط إذا كان يحتوي تغييرات غير منقولة إلى فرع المشروع الرئيسي.

## قاعدة العمل من الآن

1. أي تعديل للمتجر التقليدي يبدأ من `main`.
2. أي تعديل للمنصة يبدأ من `builder/v1-platform`.
3. أي تعديل لتطبيق الديون يبدأ من `debt-store-build`.
4. لا ننشئ فرعًا جديدًا قبل تحديد المشروع الذي ينتمي إليه.
5. لا ننقل ملفات بين المشاريع لمجرد ترتيب الشكل إذا كان ذلك قد يكسر التشغيل أو CI.
6. أي فرع مؤقت انتهى دوره يُراجع مقابل فرعه الرئيسي ثم يؤرشف أو يُحذف لاحقًا.
