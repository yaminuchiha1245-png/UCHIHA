# تقرير تنفيذ UCHIHA Builder — 2026-07-30

## نطاق هذه الدفعة

تم تنفيذ دفعة فعلية داخل `builder/` فقط على الفرع المحلي
`builder/v1-platform`. لم يُعدّل المشروع القديم خارج المجلد، ولم يحدث دمج إلى
`main` أو نشر إلى Railway أو اتصال بقاعدة الإنتاج.

هذه الدفعة ليست إعلانًا بأن كامل المنصة الضخمة انتهت؛ هي Vertical Slice موسعة
ومرتبطة بالـBackend للواجهات والحماية والعمليات الأساسية التالية.

## ما نُفّذ

### متجر العميل

- هيدر ديناميكي: شعار المتجر، رجوع، إشعارات، صورة حساب، رصيد حقيقي وقائمة.
- شريط سفلي ثابت بالترتيب المعتمد وسلوك Safe Area.
- Design Tokens تأتي من إعداد المتجر، مع ألوان النجاح والتحذير والخطر وFavicon.
- سلة محلية متعددة المنتجات، تعديل/حذف، إجمالي، ودفع ذري من المحفظة.
- قائمة جانبية كاملة بمسارات الحساب، دون خلط API مع بطاقة UCHIHA Builder.
- تعطيل عناصر توثيق الهوية وAPI والدعم العائم والوضع الفاتح حسب إعداد المتجر.
- دعم تحميل وفشل وغياب جلسة العميل دون عرض رصيد وهمي.

### المحفظة والمدفوعات والطلبات

- Ledger موسع بنوع العملية والرصيد قبل/بعد والعمولة والمرجع.
- إدخال مبلغ يدوي فقط، عمولة نسبة/ثابتة/حد أدنى، وحساب خادمي للصافي.
- إثبات صورة JPG/PNG/WebP مع فحص MIME والتوقيع الحقيقي وحد حجم لكل طريقة.
- دفعات العميل بفلاتر وبحث وتفاصيل وإثبات يُجلب فقط عند فتح التفاصيل.
- طلبات العميل بفلاتر تاريخ/حالة/بحث وملخص إنفاق وتفاصيل مراحل التنفيذ.
- شراء المحفظة متعدد العناصر داخل Transaction مع Row Locks وIdempotency.

### الحماية

- TOTP متوافق مع تطبيقات Authenticator.
- تحدي تسجيل دخول منفصل عند تفعيل 2FA.
- Recovery Codes مخزنة كـHash وتستهلك مرة واحدة.
- تغيير كلمة المرور، الجلسات، إنهاء الجلسات الأخرى، سجل أمان وتنبيهات.
- Secret TOTP مشفر ولا يعاد عرضه بعد التفعيل.

### Telegram

- كود ربط من 6 أرقام باستخدام مولد عشوائي مشفر.
- الكود قصير العمر، يستخدم مرة واحدة، ويخزن كـHash.
- ربط Telegram User ID بحساب العميل نفسه دون إنشاء محفظة جديدة.
- منع ربط معرف Telegram بأكثر من عميل في المتجر، مع Audit للفك والربط.

### توثيق الهوية

- ميزة اختيارية حسب إعداد المتجر.
- مسودة، إرسال، قيد المراجعة، طلب تعديل، موثق ومرفوض.
- تشفير رقم الوثيقة ومحتوى صور الوجهين والسيلفي بـAES-256-GCM.
- التحقق من نوع الصورة والتوقيع والحجم، وعدم التخزين داخل `public/`.
- وصول خاص للعميل وإدارة المتجر مع `private, no-store` وسجل مراجعات.
- إعداد حد الملف ومدة الاحتفاظ ضمن إعدادات تجربة المتجر.

### Storefront Catalog API

- API قراءة للأقسام والمنتجات والتفاصيل والسعر والتوفر فقط.
- لا وصول إلى المحافظ أو الدفعات أو العملاء أو الهوية أو مزود المنتجات.
- مفاتيح مخزنة كـHash، Secret يظهر مرة واحدة، إلغاء وإعادة توليد.
- صلاحيات قراءة، IP Allowlist وRate Limit لكل دقيقة.
- رابط ديناميكي حسب Slug وBase Domain، وأمثلة cURL/JavaScript/Python/PHP.

### العزل والإدارة

- Migrations `018_storefront_account.sql` و`019_storefront_account_rls.sql`.
- جميع الجداول الجديدة مربوطة بـ`tenant_id` و`store_id` مع RLS.
- Endpoints وشاشة مالك لإعدادات تجربة المتجر وقنوات الدعم ومراجعة طلبات الهوية.
- صلاحية عرض ملفات KYC ومراجعتها محصورة بمالك المتجر، مع CSRF وAudit.
- Maintenance تحذف ملفات الهوية ورقم الوثيقة والتفاصيل الحساسة بعد مدة الاحتفاظ.
- Seed لمتجر UCHIHA التجريبي فقط؛ الهوية السوداء والحمراء ليست ثابتة للعملاء.

## الفحوص المنفذة

- `npm run check`: ناجح لكل ملفات JavaScript/Node المشمولة.
- 27 اختبار وحدة/حماية/صيانة ناجح، وتشمل Base32 وRFC 4226 وTOTP وRetention وHTTP Hardening.
- فحص HTML: لا توجد IDs مكررة في `store.html` أو `account.html` أو `account-admin.html` أو `admin.html`.
- `git diff --check`: ناجح ولا توجد أخطاء Whitespace.
- فحص أسرار: لا يوجد ملف `.env` حقيقي أو Private Key داخل المشروع.

## قيد الاختبار

تشغيل `npm test` الكامل في بيئة العمل الحالية أعطى 27 اختبارًا ناجحًا، وتوقفت
أربعة ملفات اختبار تكامل قبل التنفيذ لأن حزمة `pg` داخل `node_modules` غير
مكتملة. تعذر إصلاح التثبيت محليًا بسبب عدم توفر اتصال npm من هذه البيئة. هذا
عائق بيئي، ولا تُعتبر ملفات التكامل الأربعة ناجحة أو فاشلة وظيفيًا؛ يجب تشغيل
`npm ci && npm test` في Codespaces أو CI قبل الدمج.

## ما بقي خارج هذه الدفعة

- Object Storage فعلي وروابط Signed URL قصيرة العمر للملفات؛ التخزين الحالي خاص
  ومشفر داخل قاعدة البيانات ومناسب للتجربة، وليس لإنتاج ملفات كثيفة.
- تشغيل التكامل الكامل على PostgreSQL حقيقية، Telegram حقيقي، Provider حي،
  Android APK وiOS IPA.
- أي نشر أو تعديل `main` أو Railway، وهو متروك عمدًا حسب تعليمات الحماية.
