# إدارة العمليات المالية في UCHIHA Builder

تعمل هذه الواجهات داخل متجر واحد فقط، وتتطلب جلسة مالك المتجر وCSRF صالحًا. لا يسمح للمحرر أو الموظف بتنفيذ تعديل مباشر على الرصيد أو إعدادات الدفع الحساسة.

## لوحة الإدارة

```text
/admin/:storeId/payments
```

تضم اللوحة:

- مراجعة طلبات الإيداع وقبولها أو رفضها.
- إنشاء طرق الدفع وتعديلها وتفعيلها وتعطيلها وترتيبها.
- البحث في العملاء وتصفية حالتهم.
- حظر العميل أو إعادة تفعيله، مع إلغاء جلساته عند الحظر.
- إضافة أو خصم رصيد يدوي بسبب موثق.
- البحث في الطلبات وتحديث حالة التنفيذ الآمنة.
- قراءة سجل التدقيق المالي وإشعارات مالك المتجر.

## قواعد تعديل الرصيد

- يتطلب كل تعديل `idempotency-key` مستقلًا.
- يعاد نفس الرد عند تكرار المفتاح مع نفس البيانات.
- يرفض المفتاح نفسه عند تغيير المبلغ أو السبب.
- تقفل محفظة العميل قبل التعديل.
- يمنع أن يصبح الرصيد سالبًا.
- تنشأ حركة Ledger وسجل Audit وإشعار للعميل وحدث Outbox داخل Transaction واحدة.

## حالات الطلب التي يمكن للإدارة تغييرها

يسمح حاليًا بالحالات التشغيلية فقط:

- `processing`
- `completed`
- `partial`
- `failed`
- `requires_review`

لا تنفذ حالة `cancelled` استردادًا ماليًا تلقائيًا، لذلك لا تسمح الواجهة المالية بها قبل بناء تدفق Refund مستقل ومراجعته.

## العزل والحماية

- جميع الاستعلامات مقيدة بـ`tenant_id` و`store_id`.
- تعديل طرق الدفع والأرصدة ومراجعة الإيداع محصور بدور `owner`.
- إشعارات الإدارة وسجلات Idempotency الجديدة محمية بسياسات RLS.
- لا تعرض الواجهة Tokens أو بيانات المزود الحقيقية.
- لا توجد موافقة تلقائية على إثبات التحويل.
