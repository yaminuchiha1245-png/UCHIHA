# ربط FreeRADIUS

يعمل UCHIHA Agent على نفس مضيف FreeRADIUS ويربط على `127.0.0.1:8790` فقط. يزامن دليل الحسابات المشفّر محليًا، ينفذ مصادقة PAP حتى عند انقطاع الإنترنت، ويحفظ أحداث المصادقة وAccounting أولًا في SQLite ثم يرسلها إلى API المركزي بتوقيع HMAC.

## التثبيت

1. انسخ المستودع وثبّت Node.js 24.
2. اضبط متغيرات قسم `RADIUS_AGENT_*` و`UCHIHA_*` في ملف خدمة systemd.
3. انسخ `mods-available/uchiha_rest` إلى إعداد FreeRADIUS وأنشئ رابطًا في `mods-enabled`.
4. ادمج محتوى `virtual-server-snippet.conf` في الأقسام المطابقة من الـvirtual server. يعيد الوكيل `Cleartext-Password` إلى FreeRADIUS محليًا فقط، فتتولى وحدات PAP/CHAP/MS-CHAP القياسية التحقق وترسل نتيجة القبول أو الرفض إلى `/post-auth`. اترك طرق EAP في مسارها المعتاد.
5. شغّل `freeradius -XC` للتحقق من الإعداد قبل إعادة التشغيل.
6. شغّل `npm run start:radius-agent`، ثم افحص `http://127.0.0.1:8790/health`. يجب أن تكون `cachedPrincipals` أكبر من صفر وأن يظهر وقت `directorySyncedAt` حديثًا.

لا تعرّض منفذ 8790 للإنترنت، ولا تستخدم السر نفسه بين الموصل المحلي والتوقيع المركزي ومفتاح تشفير الذاكرة المحلية. اختبر الإعداد النهائي بأداة `radtest` في شبكة معملية قبل توجيه أجهزة العملاء إليه.

## تنفيذ أوامر MikroTik

1. من تطبيق المالك افتح الشبكة واضغط «مفتاح الوكيل»، ثم احفظ القيمة مرة واحدة في `RADIUS_AGENT_SIGNING_SECRET`.
2. انسخ `routers.example.json` إلى `/etc/uchiha-radius/routers.json` واستبدل القيم. أعطِ مستخدم RouterOS أقل الصلاحيات اللازمة لإدارة `/ppp/secret` و`/ppp/active` فقط.
3. اجعل مالك الملف مستخدم الخدمة وصلاحيته `0600`، وضع شهادة CA الخاصة بالموجّه بجانبه.
4. استخدم API-SSL على المنفذ `8729`. الوكيل يرفض شهادات TLS غير الموثوقة ولا يحتوي خيارًا لتعطيل التحقق.
5. اضبط `RADIUS_COMMAND_ADAPTER=routeros` و`RADIUS_ROUTERS_FILE=/etc/uchiha-radius/routers.json`.

يسحب الوكيل أوامر تعليق/تفعيل حساب PPP وفصل الجلسة بتوقيع خاص بكل شبكة، ويؤكد النتيجة للخادم. الأوامر قابلة للإعادة بأمان إذا انقطع الاتصال أثناء التنفيذ.
